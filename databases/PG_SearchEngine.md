### Stemming

- Works via suffix removal based on existing rules created based on the English Language

```sql
SELECT to_tsvector('english', 'The reactor was venting plasma');

select
    to_tsvector('english', 'The coolant loop was venting plasma across the number two reactor')
      @@ plainto_tsquery('english', 'venting plasma') as matched
```

### Generated column

A generated column is generated by postgres from the columns instead of user inputting the value

```sql
CREATE TABLE logs (
    id          bigint GENERATED ALWAYS AS IDENTITY,
    timestamp   timestamptz NOT NULL,
    index     text NOT NULL,
    message     text NOT NULL,
    search_vector tsvector GENERATED ALWAYS AS (
      to_tsvector('english', message)
  ) STORED
);
```

### General Inverted Index

Required because multiple values are indexable in a single row

```sql
CREATE INDEX logs_search_idx
ON logs
USING GIN (search_vector);
```

### Search

```sql
SELECT *
FROM logs
WHERE search_vector @@
      to_tsquery('english', 'connection');
# Outputs the row

SELECT *
FROM logs
WHERE search_vector @@
      to_tsquery('english', 'database & connection');
# Outputs the row

SELECT *
FROM logs
WHERE search_vector @@
      to_tsquery('english', 'database | conection');
# Outputs the row

SELECT *
FROM logs
WHERE search_vector @@
      to_tsquery('english', 'conection');
# Outputs nothing
```

### Fuzzy search

- Fuzzy search can be implemented in various ways such as edits in a string, cosine similarity (Storing each log event as a vector using a generated column and then running a cosine similarity search), ngram etc.

#### ngram (trigram)

- The words are split in groups of 3
- 2 strings are considered a match if x% of the trigrams match. The threshold is defined as:

```sql
SHOW pg_trgm.similarity_threshold;

pg_trgm.similarity_threshold 
------------------------------
 0.3
```

- In the same table, create a new index on the message column of type GIN where data is ingested in the index through gin_trgm_ops

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX logs_message_trgm_idx
ON logs
USING GIN (message gin_trgm_ops);
```

- Search

```sql
select * from logs where message % 'databse connection'
# Works

select * from logs where message % 'databse'
# Does not work
```

Why: The similarity score is calculated between the message and the user query. The number of trigrams which match are less than the threshold. This approach matches strings to strings and not search for a word in a string

#### ngram Limitation

- The storage requirements explode because the string characters repeat across the ngrams the string is divided into
- Only string to string searches work

#### Workaround

- Store the stemmed data with a GIN
- For each word in the user query, iterate the trie with a maximum edit distance of x and then perform a search on the expanded search space using to_tsquery.
